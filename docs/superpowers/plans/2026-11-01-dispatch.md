# /dispatch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One command the owner starts in the evening: it refreshes the task
list, interviews the owner on every issue that waits on a human, then runs up
to `--pairs` headless `/ship` sessions at once on groups whose files do not
overlap, absorbs what each files, and writes one morning report.

**Architecture:** The dispatcher is a session (`.claude/commands/dispatch.md`)
kept small by one Python helper, `.claude/scripts/dispatch_board.py`, which
owns every mechanical read and write: the task list's tables, readiness and
path overlap, the run's state file, the `claude -p` launch, the result and
session reads and their classification, the usage reading and the report's
facts. A second helper, `.claude/scripts/issue_decisions.py`, is the only way
an issue body gains an `## Owner decisions` entry. `/ship` and `/branch` take
one new standalone token, `--dispatched <run-dir>`. Every `.claude/` file is
written under `staging/` and landed by an `apply.sh` the owner runs.

**Tech Stack:** Python 3.12 (`py -3.12`, stdlib only, `unittest`), Git Bash
helpers under `.claude/scripts/`, `gh`, `claude -p --output-format json`,
Markdown commands with frontmatter grants.

**Spec:** docs/superpowers/specs/2026-11-01-dispatch-design.md

## Global Constraints

- Arguments: `--pairs <1-4>` required, the report recommends 2; `--lang
  <code>` defaults to `en` (spec §3).
- The dispatcher runs in the main checkout on a clean `main`; off `main`,
  dirty, or ahead of `origin/main` stops it before the interview; after each
  merge `git pull --ff-only` (§3).
- From step 0 to the report the dispatcher is the task list's only writer and
  re-reads it before every write (§4).
- A row waiting on a human carries `OWNER` in *Depends on* (§4).
- Answers go in `## Owner decisions`, one entry per answer, date, question
  and answer, in English whatever `--lang` is; the helper refuses any other
  shape (§5).
- Executor: `claude -p` in its own worktree, the group's *Model*,
  `--output-format json`, never `bypassPermissions` or
  `--dangerously-skip-permissions` (§6.2).
- Result: `<run-dir>/<group>.json`; `outcome` is `merged`, `handed-back` or
  `stopped`; `review_end` is `clean`, `comments-rule`, `plan` or `ceiling`;
  unparsable or missing is a failed run, never a success (§6.3).
- Five-hour window: wait for its reset, relaunch the same group in the same
  worktree; a crash relaunches once, a second is a hand-back; a deliberate
  stop is never retried (§6.4, §2).
- Night ends only on: the `seven_day` window at 1% left or less (dropped and
  reported "not read" where no cheap source exists); nothing ready and
  nothing running; the owner's stop file (§8).
- All run state under `artifacts/dispatch/<run>/` (gitignored); the report at
  `artifacts/dispatch/<run>/report.md`, in `--lang`, six sections, ending
  with the apply line (§9, §10).
- The dispatcher grants no agent type and denies every one (§11).
- Windows: decode subprocess output as UTF-8, never `text=True`'s cp1252;
  Git's `bash.exe` by absolute path, never bare `bash`; `127.0.0.1`, never
  `localhost` (§11).
- Suites fake `claude -p`, `gh` and the usage reading; none starts a session
  or touches GitHub (§12).
- `.claude/` files land as `staging/` plus an `apply.sh`, `settings.json`
  last (§11).

## Review Focus

1. A result that claims `merged` for a PR GitHub shows open, merged at
   another oid, or on another branch — owned by Task 3's
   `test_a_merge_claim_github_does_not_show_is_a_stop`.
2. A result naming another group, other issues, or an unknown key (an
   executor's own text, possibly steered by issue text) — owned by Task 3's
   `test_a_result_for_another_group_is_no_result`.
3. The task list edited by another session between the dispatcher's read and
   its write — owned by Task 2's
   `test_a_move_rereads_the_file_and_keeps_another_sessions_edit`.
4. Resume relaunching over an executor still alive, or adopting a worktree
   this run never forked — owned by Task 3's
   `test_resume_adopts_only_its_own_dead_groups`.
5. Session output outside cp1252 (an em dash, Cyrillic under `--lang ru`)
   and a rate-limit notice whose reset cannot be parsed — owned by Task 3's
   `test_session_output_is_read_as_utf8_and_an_unparsed_reset_is_a_crash`.

- [ ] **Step 7: decision gates**, written at the top of `spike.md`:
